Un moteur logique indépendant du code Android\n\n\n\nLes règles métier évoluent plus vite que l’application. Il faut donc éviter les chaînes de if/else dispersées dans les ViewModels.\n\n\n\nExemple de mauvaise logique :\n\n\n\nif (species == CHENE && diameter > 50 && quality == A) {\n\n    price *= 2.5\n\n}\n\n\n\nLa règle devrait être déclarative, versionnée et testable :\n\n\n\n{\n\n  \"ruleId\": \"WOOD_VALUE_OAK_A_50\",\n\n  \"version\": \"2026.1\",\n\n  \"conditions\": {\n\n    \"all\": [\n\n      { \"field\": \"speciesGroup\", \"operator\": \"equals\", \"value\": \"OAK\" },\n\n      { \"field\": \"diameterCm\", \"operator\": \"greaterOrEqual\", \"value\": 50 },\n\n      { \"field\": \"quality\", \"operator\": \"equals\", \"value\": \"A\" }\n\n    ]\n\n  },\n\n  \"effects\": [\n\n    {\n\n      \"type\": \"PRICE_MULTIPLIER\",\n\n      \"value\": 2.5\n\n    }\n\n  ]\n\n}\n\n\n\nLes moteurs inspirés de JSON Logic permettent justement de représenter des ensembles de règles sous forme de données JSON plutôt que de les figer dans l’interface.\n\n\n\nPour GeoSylva, je recommande cependant de développer un moteur Kotlin dédié et limité, inspiré de ces standards, plutôt que d’intégrer directement un moteur JavaScript.

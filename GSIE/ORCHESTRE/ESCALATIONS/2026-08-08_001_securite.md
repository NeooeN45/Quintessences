# ESCALADE #001 — pyjwt 3 CVE HIGH sur l'authentification JWT

## Statut: EN ATTENTE DE RÉPONSE

## Question

Faut-il mettre à jour pyjwt de 2.10.1 → 2.13.0 pour corriger 3 CVE HIGH qui touchent directement l'authentification JWT RS256 de l'API GSIE ?

## Contexte

- **pyjwt 2.10.1** a 7 CVE dont 3 HIGH :
  - **CVE-2025-30204** — bypass de l'allow-list d'algorithmes (un attaquant peut forcer un algorithme non autorisé)
  - **CVE-2024-53861** — clé publique utilisée comme secret HMAC (permettrait de forger des tokens si HS256 est accepté)
  - **CVE-2023-46083** — validation incorrecte du claim `iss` (bypass possible)
- **Impact direct** : `core/auth.py:138` utilise JWT RS256 avec pyjwt. Les CVE touchent la validation des tokens.
- **Mitigation actuelle** : `core/config.py:241` force `jwt_algorithm: Literal["RS256"]` — impossible de dégrader vers HS256 via config. Mais CVE-2025-30204 pourrait bypass cette restriction.
- **Risque** : si un attaquant exploite CVE-2025-30204, il peut forger des tokens JWT valides avec HS256 + clé publique → authentification bypassée.
- **Utilisateurs impactés** : tous les utilisateurs authentifiés de l'API GSIE.

## Options

A) **Mettre à jour pyjwt → 2.13.0 maintenant** (recommandé par la loop)
   - Impact : mise à jour simple, pyjwt 2.13.0 est rétrocompatible
   - Risque : faible (changement de version mineure)
   - Temps : 15 min (uv lock + tests)

B) **Mettre à jour pyjwt + tous les packages avec CVE HIGH** (pyjwt, python-multipart, cryptography)
   - Impact : 3 mises à jour, nécessite re-test complet
   - Risque : moyen (cryptography 49→50 peut casser des choses)
   - Temps : 1h

C) **Attendre et planifier** — les CVE sont documentées, mitigation RS256 en place
   - Risque : CVE-2025-30204 pourrait bypass la mitigation
   - Temps : 0

## Recommandation

**A** — Mettre à jour pyjwt 2.10.1 → 2.13.0 immédiatement. C'est une mise à jour simple et rétrocompatible qui corrige 3 CVE HIGH sur le composant le plus sensible (auth JWT). Les autres mises à jour (python-multipart, cryptography) peuvent suivre dans un second temps.

## Impact

- Temps estimé : 15 min
- Fichiers : `pyproject.toml`, `uv.lock`
- Breaking : non (changement de version mineure 2.10→2.13)
- Tests : exécuter `pytest tests/unit/test_auth*.py` + `tests/mutation/harnais.py`

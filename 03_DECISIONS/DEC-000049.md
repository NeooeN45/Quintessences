# DEC-000049 — Contrats d'interface GeoSylva ↔ moteurs GSIE

| Champ | Valeur |
|---|---|
| **ID** | DEC-000049 |
| **Statut** | Validé |
| **Date** | 2026-08-03 |
| **Décideur** | Camille Perraudeau (Fondateur) |
| **RFC liée** | RFC-0033 |
| **Supersède** | Aucun |
| **Préserve** | DEC-000048, CON-001, CON-004, CON-005, CON-010, ADR-009 |
| **Nature** | Décision d'architecture applicative et de contrats d'interface |

## Décision

GeoSylva 3.0 délègue aux moteurs GSIE via le canal 1 (Wi-Fi/4G stable) en
consommant l'API GSIE (FastAPI, JWT RS256), pas en appelant les moteurs en
direct. Un contrat d'interface unifié est adopté : enveloppe commune de
requête (`requete_id`, `session_id`, `auteur`, `moteur_cible`, `payload`)
et enveloppe commune de réponse (`resultat_id`, `moteur_version`,
`source_reference`, `evidence_level`, `chaine_inference`).

Huit endpoints moteurs, deux endpoints d'orchestration (chaîne
Correlation → Reasoning → Diagnostic, et Diagnostic → Recommendation →
Simulation) et un endpoint de pull serveur→mobile sont spécifiés. Un SDK
Kotlin encapsule l'authentification, le cache local SQLCipher, la file
`EN_ATTENTE_AMPLIFICATION` (WorkManager) et la gestion d'erreurs.

## Contrat retenu

| Élément | Règle |
|---|---|
| Authentification | JWT RS256 (Bearer), refresh automatique côté SDK |
| Isolement | RLS PostgreSQL par `auteur` (compte Quintessences) |
| Idempotence | `requete_id` = clé d'idempotence ; même requête → même `resultat_id` |
| Concurrence | `version` (optimistic locking) ; 409 si version diffère |
| Rate limit | 60 req/min par compte, 10 req/min par moteur lourd |
| Cache local | Table `gsie_cache` (SQLCipher) avec expiration et détection obsolescence |
| Mode hors ligne | Appel échoué → `EN_ATTENTE_AMPLIFICATION`, retry WorkManager 15s→1h |
| Pull serveur→mobile | `GET /api/v1/sync/geosylva/resources/{client_id}?since={ts}` paginé cursor-based |
| Conflits | Écran `ConflictResolutionScreen` ; aucun écrasement automatique silencieux |

## Garde-fous

- **ADR-009** : toute réponse moteur expose `source_reference` +
  `evidence_level`. Défaut bloquant sinon.
- **GSIE-CON-001** : toute recommandation est `contournable: vrai`.
- **GSIE-CON-004** : toute conclusion expose `chaine_inference`.
- **GSIE-CON-005** : `requete_id` + `resultat_id` tracés en session martelage.
- **Offline-first** : un appel échoué ne bloque jamais le cœur forestier.

## Phase

Phase P4 de la roadmap GeoSylva 3.0 (GEOSYLVA-003 §12.4). Dépendances :
P0 (corrections audits) + P3 (moteurs scientifiques locaux) terminés.

## Preuves d'acceptation attendues

1. Tests contractuels par endpoint (schéma JSON + garde-fous ADR-009).
2. Mock serveur GSIE (MockWebServer) pour tests E2E.
3. Tests du cache local (expiration, obsolescence, ré-exécution manuelle).
4. Tests de résolution de conflits (local vs serveur, fusion manuelle).
5. Tests de la file `EN_ATTENTE_AMPLIFICATION` (retry exponentiel).
6. Diagnostic développeur : compteurs par moteur, latence, version.

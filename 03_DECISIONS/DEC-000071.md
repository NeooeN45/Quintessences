# DEC-000071 — Idempotence de la route métier d’orchestration

| Champ | Valeur |
|---|---|
| **ID** | DEC-000071 |
| **Statut** | Proposé |
| **Date** | 2026-08-15 |
| **Décideur** | Fondateur — ratification requise |
| **Périmètre** | API GSIE, orchestration, HA et preuves `analysis_run` |
| **Précédents** | DEC-000064, DEC-000065 |

## Contexte

Le banc HA doit éprouver une route métier réelle, et non uniquement les sondes
`/health` et `/ready`. Une application mobile peut répéter une requête après un
timeout réseau, éventuellement sur un autre replica. Sans contrat explicite,
le retry relancerait les quatre moteurs et créerait plusieurs preuves pour une
même demande GeoSylva.

## Décision proposée

La route `POST /api/v1/orchestration/analyse` adopte le contrat suivant :

- `requete_id` est l'identifiant métier stable d'une demande ;
- `Idempotency-Key`, lorsqu'elle est envoyée, doit être égale à `requete_id` ;
- l'empreinte SHA-256 est calculée sur le JSON canonique complet ;
- une même empreinte retourne la preuve existante sans réexécuter les moteurs ;
- un contenu différent avec le même identifiant est refusé HTTP 409 ;
- une ligne historique sans empreinte est refusée plutôt que réutilisée ;
- PostgreSQL sérialise la course par verrou transactionnel et index unique
  partiel ;
- le contrat reste limité à cette route et n'autorise aucune promotion de
  données, aucun FETCH et aucun SLO de production.

## Portes de preuve

La décision ne pourra passer à `Validé` qu'après :

1. tests unitaires et PostgreSQL réels verts ;
2. migration 0049/0050 réversible et alignée au modèle ;
3. replay HTTPS vérifié sur deux replicas avec CA explicite ;
4. douze requêtes métier réussies pendant le drainage d'un replica ;
5. maintien des scénarios Redis dégradé et de la séparation test/staging/
   production ;
6. relecture du run GitHub Actions sur le commit intégrant cette décision.

# DEC-000052 — Hardening authentification GSIE API (7 lacunes)

| Champ | Valeur |
|---|---|
| **Statut** | Validated |
| **Date** | 2026-08-05 |
| **Décideur** | Fondateur |
| **Portée** | GSIE/API — module `gsie_api.auth` |
| **Précède** | DEC-000044 (identité canonique multi-fournisseurs) |

## Contexte

L'audit du système d'authentification GSIE (DEC-000044) a identifié 7
lacunes empêchant d'atteindre un niveau « très avancé » :

1. MFA/2FA absente (TOTP, WebAuthn, recovery codes)
2. Lockout par compte partiel (rate limiting sans verrouillage)
3. Sessions actives absentes (pas de logout sélectif)
4. OIDC générique en stub (DB prête, pas de vérificateur)
5. Force mot de passe absente (pas de HIBP, zxcvbn, historique)
6. Détection réutilisation refresh token partielle
7. Événements auth non persistés dans audit_log

## Décision

Combler les 7 lacunes en une seule passe cohérente, avec :

- **MFA TOTP** (RFC 6238) via `pyotp`, secret chiffré Fernet, codes de
  récupération Argon2id à usage unique.
- **Lockout progressif** via Redis (distribué) ou mémoire (dev), fenêtre
  glissante atomique, seuil et durée configurables.
- **Sessions actives** persistées en DB (`active_session`), traçage par
  appareil (User-Agent, IP, device name), révocation sélective.
- **OIDC générique** via découverte JWKS standard, validation
  audience/issuer, configurable par `GSIE_OIDC_PROVIDERS`.
- **Force mot de passe** via HIBP k-anonymity (préfixe SHA-1 seul envoyé)
  + zxcvbn (score 0-4, seuil minimum configurable).
- **Détection réutilisation** : log d'avertissement quand un refresh
  token déjà rotaté est réutilisé (indicateur de vol).
- **Événements auth** : bridge fire-and-forget vers `audit_log`
  existant (login, lockout, MFA, sessions, OIDC).

## Conséquences

- 5 nouvelles tables en schéma `gsie_rgpd_identites` (migration
  `20260803_0034`).
- 2 nouvelles dépendances : `pyotp`, `zxcvbn`.
- 11 nouvelles variables d'environnement (documentées dans `.env.example`).
- 24 nouveaux tests unitaires (`test_auth_hardening.py`).
- Aucun breaking change sur l'API existante — les nouveaux endpoints
  sont additifs (`/auth/mfa/*`, `/auth/sessions/*`, `/auth/oidc/*`,
  `/auth/password/strength`).

## Alternatives considérées

- **WebAuthn** au lieu de TOTP : rejeté pour la phase 1 (complexité
  client, support navigateur inégal). TOTP est universel et suffisant
  pour le niveau visé. WebAuthn reste une extension future.
- **Captcha** au lieu de lockout : rejeté (UX dégradée, accessibilité).
  Le lockout progressif est moins intrusif et suffisant avec le rate
  limiting existant.
- **Historique de mots de passe** : non implémenté (YAGNI — HIBP +
  zxcvbn couvrent le risque principal). Pourrait être ajouté si
  exigence de conformité future.

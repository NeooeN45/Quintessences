# DEC-000076 — Création de compte native dans GeoSylva

| Champ | Valeur |
|---|---|
| **ID** | DEC-000076 |
| **Statut** | Validé — tranche d’implémentation V1 autorisée le 2026-08-29 |
| **Date** | 2026-08-29 |
| **Décideur** | Fondateur |
| **Périmètre** | GeoSylva Android 3.0 → 3.1, création du compte Quintessences |
| **Précédents** | DEC-000074, DEC-000075, GEO-005, IDENTITE-001 |

## Contexte

Le bouton de création de compte de GeoSylva ouvrait auparavant la page web
publique. Cette rupture de contexte est inadaptée à la recette mobile et
multiplie les surfaces de formulaire. Le dépôt d'identité Android, le contrat
API d'inscription et le stockage chiffré de session existent déjà.

## Décision

GeoSylva expose une route native dédiée
`settings/account/register`. Cette page reprend la qualité visuelle de l'écran
de connexion et reste adaptée à l'écran mobile. Elle réutilise sans copie :

- `LoginScreen` et son socle visuel Compose ;
- `LoginViewModel` et `LoginMode.REGISTER` pour l'état et la validation ;
- `IdentityRepository.register` pour l'appel au contrat GSIE ;
- le stockage de session déjà utilisé par la connexion.

Le parcours ne lance pas Chrome et ne stocke aucun mot de passe, jeton ou
secret dans la base locale GeoSylva. La robustesse immédiate affichée dans
l'interface est informative ; la validation serveur et le hachage Argon2id
restent autoritatifs. Le compte demeure optionnel afin de préserver le mode
hors ligne.

La page n'invente pas d'acceptation juridique. Les consentements versionnés
doivent être reliés explicitement au parcours d'inscription via le contrat
existant avant de déclarer le gate RGPD fermé.

## Conséquences et preuves attendues

- une route `Screen.Register` et un wrapper `RegisterScreen` sont ajoutés ;
- la navigation depuis l'accueil et Réglages conserve le même parcours ;
- une compilation `assembleDebug` et une installation ADB sur le S25 Ultra sont
  requises ;
- la preuve actuelle couvre l'affichage natif, l'absence de navigateur et le
  refus d'un formulaire vide ;
- restent à prouver la création réelle avec adresse de test, la vérification
  e-mail, Google, la restauration, la purge locale et l'isolation de deux
  comptes ;
- aucune push, fusion ou mise en production n'est autorisée par cette décision.

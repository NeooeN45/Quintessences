# DEC-000075 — Finalisation RGPD différée et anonymisation irréversible du compte

| Champ | Valeur |
|---|---|
| **ID** | DEC-000075 |
| **Statut** | Validé — tranche d’implémentation V1 autorisée le 2026-08-26 |
| **Date** | 2026-08-26 |
| **Décideur** | Fondateur |
| **Périmètre** | Compte Quintessences, API GSIE, données synchronisées GeoSylva |
| **Précédents** | DEC-000074, DEC-000046, GEO-005, IDENTITE-001 |

## Contexte

La demande de suppression existe déjà : elle révoque les sessions, place le
compte en `pending_deletion` et ouvre un délai d’annulation. Il manque le
traitement automatique arrivé à échéance. Une suppression physique du compte
est incompatible avec les clés étrangères `RESTRICT` qui garantissent la
continuité des organisations et des invitations partagées.

## Décision

À l’échéance, un worker serveur dédié exécute une fonction PostgreSQL
`SECURITY DEFINER`, idempotente et bornée par lots. Le compte devient un
tombstone technique (`status=disabled`, `deleted_at` renseigné, nom et
identifiants de connexion supprimés) ; il ne peut plus être authentifié ni
restauré.

La finalisation purge les données strictement rattachées au compte :

- liens de fournisseurs et identifiants locaux ;
- rôles, consentements, demandes d’action, changement d’e-mail, MFA ;
- sessions actives, refresh révoqués et échecs de connexion ;
- abonnement et droits personnels de billing ;
- appartenances d’organisation et répliques serveur `geosylva_parcels`.

Les organisations et leurs workspaces sont conservés lorsqu’ils sont partagés.
Les références `created_by`/`invited_by` pointent alors vers le tombstone, ce
qui évite de casser l’historique ou d’effacer les données d’autres membres.
Les événements d’audit restent append-only pour leur intégrité ; les
`actor_email` historiques sont toutefois masqués par une exception technique
strictement bornée à l’anonymisation RGPD. Un nouvel événement `delete` sans
donnée personnelle confirme la finalisation.

Le worker n’est pas exposé par HTTP. La seule annulation utilisateur reste le
code à usage unique avant échéance. La restauration d’une sauvegarde reste une
opération d’infrastructure distincte et ne réactive jamais ce tombstone.

## Portes de preuve

1. migration appliquée et fonction appelée par le rôle applicatif sans droit
   DDL ;
2. test contrôlé sur un compte synthétique avec données liées ;
3. rejeu idempotent et concurrence annulation/finalisation vérifiés ;
4. absence de connexion, export, session ou donnée GeoSylva après finalisation ;
5. preuve de non-régression des organisations partagées et de l’audit ;
6. documentation de la durée de conservation audit/billing validée
   juridiquement avant production.

Cette décision n’autorise ni push, ni fusion, ni déploiement de production.

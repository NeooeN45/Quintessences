# DEC-000040 — Tables transverses laissées dans `public`

| Champ | Valeur |
|---|---|
| **ID** | DEC-000040 |
| **Statut** | Draft |
| **Date** | 2026-07-31 |
| **Décideur** | Camille Perraudeau (Fondateur) — en attente de validation |
| **Supersède** | Aucun |
| **Préserve** | `DEC-000019` (PostgreSQL+PostGIS+AGE), `GSIE-PROMPT-0027` (schémas de domaine) |
| **Nature** | Décision d'architecture de données, sans effet constitutionnel |
| **RFC associée** | `RFC-0029` (schémas de domaine et rôles par moteur) |

## Contexte

La migration vers 7 schémas de domaine (`gsie_botanique`, `gsie_foret`,
`gsie_gouvernance`, `gsie_climat`, `gsie_pedologie`, `gsie_hydro`,
`gsie_feu`) a déplacé les tables métier de `public` vers leurs schémas
respectifs. Cependant, un audit approfondi (revue de
`GSIE/API/src/gsie_api/infrastructure/models/`) a identifié **21 tables**
qui restent dans `public` par défaut (aucun `__table_args__` avec
`schema=...`).

La question se pose : faut-il déplacer ces tables vers un schéma de
domaine, ou les laisser dans `public` ?

## Décision

**Les 21 tables transverses restent dans `public`.**

### Raison structurelle

`resource` est la table racine du métamodèle v6.2. Elle reste dans
`public` par contrainte explicite de `GSIE-PROMPT-0027`. Les 20 autres
tables transverses référencent `resource.id` directement ou
indirectement, et servent **plusieurs domaines simultanément**. Les
déplacer vers un schéma de domaine unique :

1. **Casserait la symétrie** — `resource` est dans `public`, ses tables
   transverses le sont aussi.
2. **Arbitrerait artificiellement** — `diagnostic` sert la forêt, le
   climat, la pédologie ; `flow` sert tous les moteurs ; `assertion`
   sert le raisonnement et la botanique.
3. **Compliquerait les FK** — chaque FK vers une table transverse
   devrait être qualifiée `public.diagnostic.id` au lieu de
   `diagnostic.id`, alourdissant le code sans bénéfice métier.

### Liste des 21 tables transverses dans `public`

**Noyau transverse (5)** :
- `resource` — table racine (contrainte GSIE-PROMPT-0027)
- `administrative_unit` — découpage administratif IGN
- `diagnostic` — diagnostic multi-domaine
- `model_run_input`, `model_run_output` — jonctions IA/ML

**Métadonnées écologiques (5)** — `ecology.py` :
- `scale_context` — contexte d'échelle (spatiale/temporelle)
- `phenomenon` — phénomène écologique observé
- `ecological_process` — processus écologique
- `relation_type` — type de relation entre entités
- `sampling_event` — événement d'échantillonnage

**Raisonnement (5)** — `reasoning.py` :
- `question` — question de recherche
- `hypothesis` — hypothèse scientifique
- `scenario` — scénario de simulation
- `correlation` — corrélation statistique
- `capability` — capacité du système

**Observation & mesure (6)** — `observation.py`, `spatial_temporal.py`,
`assertion.py`, `fair_rgpd.py`, `models_ai.py`, `dynamics.py` :
- `observation`, `result`, `method`, `instrument` — protocole scientifique
- `uncertainty`, `quality_assessment` — qualité des données
- `unit`, `place`, `temporal_context`, `media` — contexte spatio-temporel
- `assertion`, `assertion_participant`, `assertion_qualifier`,
  `predicate`, `evidence_assessment` — assertions épistémiques
- `flow`, `confidence_graph`, `goal`, `constraint`,
  `knowledge_lineage`, `experiment`, `ecological_state`,
  `terrain_session` — dynamique du système
- `sample`, `persistent_identifier` — FAIR
- `model`, `model_run`, `dataset`, `model_version`,
  `dataset_version`, `data_asset`, `distribution`, `feature`,
  `feature_set`, `citation` — IA/ML

### Sécurité

`gsie_application` a `SELECT/INSERT/UPDATE` sur `ALL TABLES IN SCHEMA
public` (migration 0012), sans `DELETE` (CON-010). Les tables
transverses héritent de cette politique. Aucune table RGPD ne reste
dans `public` :

- `data_subject` → `gsie_rgpd_identites`
- `consent`, `rights_statement`, `spatial_disclosure_policy`,
  `access_policy`, `sensitivity_classification` → `gsie_rgpd`
- `data_subject_consent` → `gsie_rgpd` (migration 0021)

## Conséquences

- Les 21 tables transverses restent accessibles via `public.<table>`
  sans qualification de schéma.
- Les FK vers ces tables n'ont pas besoin de qualification (`diagnostic.id`
  résout vers `public.diagnostic.id`).
- `gsie_application` conserve `SELECT/INSERT/UPDATE` sans `DELETE` sur
  ces tables.
- Une future refactorisation pourrait créer un schéma `gsie_transverse`
  si `public` devient trop encombré — mais ce n'est pas nécessaire en v1.

## Critères de clôture

La décision est satisfaite lorsque :
- les 21 tables transverses sont documentées comme telles dans les
  modèles (commentaire `# Table transverse — voir DEC-000040`) ;
- aucun test de dérive ne signale ces tables comme mal placées ;
- la suite de tests reste verte.

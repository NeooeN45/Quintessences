## Décision

Redéployer localement l'API GSIE et le worker outbox depuis le commit
`6986e80`, puis vérifier en conditions réelles la santé, la migration, la
politique FETCH fermée, PostgreSQL, Redis, MinIO et le DataAsset SoilGrids déjà
certifié par DEC-000061.

Cette décision n'autorise ni un nouveau `GetCoverage`, ni l'ouverture du
registre FETCH canonique, ni une promotion de version.

## Résultat

- API et worker outbox reconstruits et sains ;
- `/health` et `/ready` : HTTP 200 ;
- PostgreSQL : migration `20260810_0048` ;
- politique déployée : SoilGrids `fetch_enabled=false` ;
- mapping déployé : `wv003` vers `wv0033` ;
- manifeste Data Registry : quatre entrées inchangées sur deux rejeux ;
- round-trip MinIO temporaire : exact et nettoyé ;
- DataAsset `a584c377-ff39-4e58-967a-7304b732bb47` : 569 octets, SHA-256
  inchangé et signature TIFF little-endian `49492a00` ;
- version SoilGrids maintenue à `discovered`.

## Réserve de performance

La charge HTTP reste fonctionnellement stable : 1 000/1 000 réponses santé
et 120/120 requêtes authentifiées réussissent, sans restart ni OOM. Le port
publié par Docker Desktop plafonne toutefois autour de 19 requêtes/s :

- concurrence 100 : p95 15,69 s ;
- concurrence 20 : p95 2,20 s ;
- séquentiel après échauffement : environ 5 à 8 ms.

Ce profil indique une saturation du chemin concurrent local à investiguer
avant de qualifier les performances de production. Il ne remet pas en cause
l'intégrité de la chaîne de données.

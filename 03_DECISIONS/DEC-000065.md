# DEC-000065 — Qualification HA Linux TLS automatisée en CI

|---|---|
| **ID** | DEC-000065 |
| **Statut** | Validated |

| **Périmètre** | Qualification HA Linux, TLS et drainage automatisé |

## Décision

Ajouter un workflow Ubuntu jetable qui construit GSIE, applique les migrations,
démarre deux replicas derrière HAProxy avec TLS vérifié, retire un replica sous
charge et échoue automatiquement si les critères provisoires sont dépassés.

Le certificat CI est éphémère, contient les SAN nécessaires et sa CA est fournie
explicitement au client. Aucun `verify=false` ou équivalent n'est autorisé.

## Portes automatiques

- uniquement des statuts HTTP 200 ;
- aucune erreur de transport ;
- p95 inférieur ou égal à 250 ms ;
- p99 inférieur ou égal à 400 ms ;
- débit supérieur ou égal à 120 req/s ;
- `/ready` reste disponible après drainage du premier replica.

## Résultat distant

Le run GitHub Actions `31479643460`, exécuté sur le commit `6442655`, est
réussi. Son artefact `ha-linux-tls-results` prouve :

- 6 000/6 000 réponses HTTP 200 et aucune erreur de transport ;
- 298,03 req/s ;
- p95 à 164,71 ms et p99 à 245,58 ms ;
- maintien de `/ready` après retrait du replica A ;
- construction, migrations, TLS vérifié et nettoyage tous réussis.

Cette exécution lève la réserve de première preuve distante du banc HA.

Le run `31488527136`, exécuté sur le commit `e9743d8`, confirme ensuite la
preuve avec l'action d'artefact épinglée. Sa première tentative a été arrêtée
avant les tests par une réinitialisation de connexion de GitHub Releases lors
du téléchargement d'Apache AGE ; le rejeu du même SHA, sans modification de
code ni contournement TLS, est réussi.

Deux nouvelles interruptions transitoires Debian ont ensuite touché la tête
`8a531ed` avant les tests : l'une sur le banc HA, l'autre dans le job Data
Registry, tandis que les mêmes constructions réussissaient dans les jobs
parallèles. Les téléchargements `apt` des images API et DB disposent désormais
de cinq reprises et de délais réseau bornés. Le téléchargement AGE ajoute les
mêmes garanties avec un temps total maximum, sans retirer la validation TLS ni
le contrôle SHA-256. Toute erreur persistante continue de bloquer la CI.

Les deux images ont été reconstruites localement après ce durcissement. Les
smoke tests confirment AGE, pgAudit, pgVector et pgBackRest dans l'image DB,
ainsi que l'utilisateur non-root et les imports API/Rust dans l'image API.

## Confirmation sur la tête finale

Le workflow HA `31494308961`, exécuté sur `f12e3cd`, est vert après les
reprises réseau bornées. Il confirme 6 000/6 000 réponses HTTP 200, zéro
erreur, 276,3 req/s, p95 175,58 ms et p99 252,82 ms. Les deux replicas,
HAProxy, TLS vérifié, le drainage et le nettoyage sont validés.

## Limites assumées

Le banc HA Linux/TLS est qualifié par cette exécution distante, mais les
requêtes longues et les écritures HTTP idempotentes ne sont pas simulées :
aucun contrat applicatif ne les rend encore testables honnêtement. Elles
nécessitent une conception dédiée avant toute publication de SLO de production.

## Hors périmètre

Aucune modification de Data Registry, FETCH, dataset ou promotion de version.

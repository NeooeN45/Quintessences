## 1. Contexte

Le fondateur a fourni des jeux d'icônes complets (PNG multi-résolutions,
assets Android `mipmap-*`, assets store Google Play/App Store) pour huit
applications : les six déjà planifiées (GeoSylva, Artemis, Ignis, Hydro,
Flora, QGISIA) et trois applications futures réservées de longue date par
`GSIE-DIR-0009` mais jamais encore créées dans `apps/` :

- **Terra** — sols / géologie
- **Aeris** — atmosphère / météo (ex-Atmos, renommée par le changelog du
  2026-08-08)
- **Atlas** — cartographie globale

`GSIE-DIR-0009` §3 et §227 réservait déjà ces trois noms comme
« applications futures » sans créer leur dossier ni leur documentation.
RFC-0037 (2026-08-06), postérieure, avait formalisé GSIE comme jumeau
numérique environnemental fédéré en listant les projections métier
alors actives (GeoSylva, Ignis, Hydro, Flora, Artemis, QGISIA) sans
reprendre la réserve Terra/Aeris/Atlas. La présente décision active le
scaffolding documentaire de ces trois applications déjà réservées ;
elle ne crée pas de nouveau domaine non anticipé, mais formalise un
enregistrement qui reste une décision du fondateur (GSIE-CON-001).

## 2. Décisions

- **Aeris**, **Atlas** et **Terra** sont créées comme nouvelles
  applications clientes planifiées de l'écosystème Quintessences,
  au même statut que Artemis/Flora/Hydro (« Planifiée », Phase 4).
- Domaines (repris de `GSIE-DIR-0009`) et moteurs GSIE consommés :
  - Aeris → Atmosphère / météo, consomme Climate, Knowledge,
    Correlation, Diagnostic.
  - Atlas → Cartographie globale, consomme GIS, Knowledge, Correlation.
  - Terra → Sols / géologie, consomme Pedology, Knowledge, Climate,
    Correlation.
- Chaque nouvelle app reçoit un `README.md` et un `GSIE_INTEGRATION.md`
  sur le modèle des apps existantes (Artemis, Flora, Hydro).
- Les icônes fournies (PNG multi-résolutions 48–1024 px, assets Android
  `mipmap-hdpi/mdpi/xhdpi/xxhdpi/xxxhdpi`, assets store 512/1024 px)
  sont rangées dans `apps/<App>/branding/icons/` pour les huit
  applications (les six existantes en plus des trois nouvelles),
  prêtes à être reliées lors du scaffolding de chaque app.
- L'icône de **GeoSylva** (seule app avec un scaffolding Android réel)
  est intégrée immédiatement : `app/src/main/res/drawable-nodpi/app_icon.png`
  remplacé par le nouveau visuel (foreground de l'adaptive icon,
  minSdk 26, pas de fallback legacy nécessaire).

## 3. Conséquences

- `README.md`, `PROJECT_MEMORY.md` et `ROADMAP.md` sont mis à jour pour
  refléter les huit applications clientes de l'écosystème.
- RFC-0037 reste la référence architecturale du jumeau numérique fédéré ;
  elle devra être amendée pour intégrer formellement Aeris/Atlas/Terra
  dans son modèle de projections métier (non fait par la présente
  décision, qui se limite à l'enregistrement des applications).
- Artemis, Flora, Hydro, Ignis restent des stubs/prototypes sans
  scaffolding applicatif — seules leurs icônes sont désormais en
  réserve, aucun code n'est créé.

## 4. Vérifications

- [x] `apps/Aeris/`, `apps/Atlas/`, `apps/Terra/` créés avec
  `README.md` + `GSIE_INTEGRATION.md` + `branding/icons/`.
- [x] `apps/Artemis/`, `apps/Flora/`, `apps/Hydro/`, `apps/Ignis/` :
  `branding/icons/` ajouté, aucun autre fichier modifié.
- [x] `apps/GeoSylva/` : icône adaptive foreground remplacée,
  dépôt Git propre avant modification.

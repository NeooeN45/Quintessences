## Décision

L'API publique GSIE est publiée derrière Cloudflare au moyen d'un tunnel
sortant. Le serveur d'origine ne publie aucun port Internet entrant ; l'API,
PostgreSQL, Redis, Mailpit et les interfaces d'exploitation restent liés à la
boucle locale ou au réseau privé Docker.

Cloudflare forme une bordure de défense et non une autorité métier. GSIE
continue de signer, vérifier et révoquer ses jetons, d'appliquer ses rôles et
de décider de chaque autorisation.

## Protocoles retenus

| Flux | Protocole et contrôles |
|---|---|
| Mobile et applications publiques → GSIE | HTTPS moderne vers Cloudflare, WAF et limitation de débit, tunnel chiffré vers l'origine, JWT GSIE RS256 |
| Serveur ou service de confiance → GSIE | HTTPS, service token Cloudflare Access ou mTLS sur un nom dédié, puis identité de charge et rôles GSIE |
| Fondateur → plan de contrôle | Nom d'hôte séparé, Cloudflare Access avec MFA et politique d'appareil, puis rôle GSIE vérifié côté serveur |
| Services d'un même hôte | Réseau privé Docker ; aucune exposition par Tunnel de PostgreSQL, Redis ou SMTP |

Un certificat mTLS ou un service token partagé n'est jamais embarqué dans
GeoSylva, Ignis, Hydro, Artemis ou une application publique : un secret livré
dans un APK ou un binaire client est extractible. Ces clients utilisent leur
session utilisateur GSIE.

## Configuration minimale

- Cloudflare Tunnel géré à distance, jeton fourni par fichier secret et
  révocable ;
- mode SSL/TLS `Full (strict)` lorsque l'origine HTTPS est utilisée, jamais
  `Flexible` ;
- cache désactivé sur les routes d'API et WebSocket autorisé ;
- règles WAF gérées et limites renforcées sur inscription, connexion,
  vérification et récupération ;
- accès administratifs sur un nom distinct, jamais sur le nom public mobile ;
- adresse cliente `CF-Connecting-IP` utilisée pour les quotas uniquement
  lorsque le mode `cloudflare_tunnel` est explicitement actif ;
- secrets Cloudflare stockés hors Git et rotation documentée ;
- contrat de traitement, localisation des journaux et transferts RGPD validés
  avant l'ouverture publique.

## Limites et réversibilité

L'application ne dépend d'aucune API propriétaire Cloudflare pour sa logique
métier. Le tunnel peut être remplacé par une autre bordure compatible HTTPS
sans modifier les contrats GSIE. API Shield avancé reste optionnel car sa
disponibilité et son coût dépendent du plan Cloudflare.

## Critères d'acceptation

1. l'origine reste inaccessible depuis Internet sans passer par Cloudflare ;
2. le tunnel se lance sous un profil Docker explicite avec un token hors Git ;
3. les quotas distinguent les clients réels sans accepter un en-tête usurpé
   en mode direct ;
4. le worker outbox possède un healthcheck propre et ne dépend plus du port
   HTTP de l'API ;
5. un runbook décrit activation, rotation, contrôle et rollback.

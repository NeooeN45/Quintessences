| Champ | Valeur |
|---|---|
| **ID** | DEC-000054 |
| **Décision** | DEC-000054 |
| **Titre** | Ouverture du chantier GSIE Territorial Mesh |
| **Statut** | Validé |
| **Date** | 2026-08-06 |
| **Décideur** | Fondateur |
| **Portée** | Transverse — architecture, gouvernance territoriale, roadmap |
| **RFC** | RFC-0036 |
| **Directive** | GSIE-DIR-0013 |
| **Complète** | DEC-000053 (Server Meshing), sans modifier DEC-000017 (Phase 4) |

## 1. Contexte

Le chantier **GSIE Server Meshing** (RFC-0035, GSIE-DIR-0012,
DEC-000053) définit l'exécution distribuée du jumeau numérique
environnemental : autorité hybride zone + type, persistance
PostgreSQL, orchestrateur de mesh, réplication par pertinence, mTLS,
offline-first, interfaces abstraites compatibles UE6.

Ce cadre ne définit pas, en revanche, l'organisation **logique,
administrative et opérationnelle** du territoire sur lequel ce mesh
s'exécute : il n'existe pas de hiérarchie de gouvernance (région,
département, territoire opérationnel), pas d'états opérationnels
explicites (froid/chaud/opérationnel/crise), pas de pool de calcul
régional intermédiaire, et pas de fédération inter-niveaux du bus
d'événements et de l'état.

Le Fondateur souhaite ouvrir un second chantier, **orthogonal et
complémentaire** au Server Meshing, pour combler ces lacunes : le
**GSIE Territorial Mesh**.

## 2. Décision

**Ouvrir le chantier GSIE Territorial Mesh** comme couche de
gouvernance territoriale, cadrée par :

- RFC-0036 (vision et principes)
- GSIE-DIR-0013 (directive fondatrice, Active)

Ce chantier ne remplace ni ne modifie le chantier GSIE Server Meshing
(RFC-0035, GSIE-DIR-0012, DEC-000053), qui reste la référence pour
l'exécution distribuée. Les deux chantiers coexistent selon la relation
d'orthogonalité décrite en RFC-0036 §6.

## 3. Décisions structurantes actées

| # | Décision | Valeur |
|---|---|---|
| D1 | Périmètre prototype v0 | Nouvelle-Aquitaine, DOD Charente (16) + Deux-Sèvres (79) |
| D2 | Hiérarchie territoriale | National → Régional → Départemental → Territoire opérationnel → Cellule → Sous-cellule |
| D3 | Source de vérité | PostgreSQL/PostGIS (ADR-011) — pas de consensus distribué introduit |
| D4 | Bus fédéré | Redis Pub/Sub par niveau, routage inter-niveaux — pas de Kafka |
| D5 | Compatibilité Server Meshing | Interfaces abstraites (ADR-015) préservées, aucun contrat modifié sans RFC |
| D6 | États opérationnels | Froid / chaud / opérationnel / crise, à chaque niveau |
| D7 | Dépendances externes | Pas de dépendance hard UE6/AWS pour la première itération |

## 4. Périmètre prototype v0

Le prototype v0 est circonscrit à la région Nouvelle-Aquitaine, avec
deux Departmental Operational Domain actifs : Charente (16) et
Deux-Sèvres (79). Ce choix permet de valider la coordination
inter-départementale au sein d'un même Regional Coordination Hub avant
toute extension inter-régionale, en cohérence avec le prototype
mono-région du Server Meshing (Landiras, Gironde).

## 5. Profondeur première itération

**Complète** : 20 livrables dédiés (gouvernance, architecture cible,
prototype v0, risques et qualité, roadmap et backlog), complétés par un
lot de synchronisation des trois fichiers racine existants. RFC-0036
et les 17 documents d'architecture/cadrage sont au statut Draft ; la
Directive est Active et la présente décision est au statut Validé.
Le détail est fixé par GSIE-DIR-0013 §5.

## 6. Impacts

- Une nouvelle RFC (RFC-0036) et une nouvelle Directive (GSIE-DIR-0013,
  Active) sont créées.
- 17 documents d'architecture, de prototype, de risques et de roadmap
  produits dans `GSIE/ARCHITECTURE/` (voir GSIE-DIR-0013 §5), en plus des
  trois livrables de gouvernance.
- Une spécification dédiée doit précéder toute évolution de modèle :
  `AdministrativeUnitModel` (`GSIE/API/src/gsie_api/infrastructure/models/business.py`)
  porte déjà une hiérarchie forestière/juridique et cadastrale. La
  hiérarchie France → Région → Département devra donc utiliser une
  entité `TerritorialAdministrativeUnit` distincte ou une correspondance
  explicite, conformément à P-TERR-08 et ADR-028. Aucune migration n'est
  autorisée sur la seule base de cette décision.
- Aucun impact immédiat sur le code Phase 4 en cours (14 moteurs, API
  GSIE, Hub UE5.8, GeoSylva, Ignis).
- Aucune modification des contrats d'interface du Server Meshing
  (ADR-010 à ADR-019).

## 7. Risques

Les risques principaux (complexité distribuée non justifiée, dérive
vers un serveur national monolithique, sous-estimation de la
fédération multi-niveaux, cas offline mal couverts, coûts et sécurité
par niveau, autorités concurrentes) sont recensés dans le registre
dédié `GSIE/ARCHITECTURE/TERRITORIAL_MESH_RISKS.md`, produit en statut
Draft conformément à GSIE-DIR-0013 §5.

## 8. Suivi

Le prototype v0 sera considéré acceptable lorsque les critères de
succès de GSIE-DIR-0013 §6 seront réunis, notamment :

- Instanciation fonctionnelle de la hiérarchie NCP → RCH
  Nouvelle-Aquitaine → DOD Charente + DOD Deux-Sèvres ;
- Transitions d'état (froid/chaud/opérationnel/crise) déclenchables et
  traçables ;
- Réplication correcte des états publiés de chaque DOD vers le RCH,
  avec convergence vérifiée ;
- Non-régression des priorités Phase 4 ;
- Traçabilité complète de toute décision structurante du chantier.

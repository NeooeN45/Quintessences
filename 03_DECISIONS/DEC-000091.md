## Contexte

La CI existante (`.github/workflows/ci.yml`) exécute déjà Trivy, Bandit/SAST,
les tests et la gouvernance — mais uniquement sur Pull Request. Aucun contrôle
sécurité ne tournait localement au commit : le `pre-commit` historique ne
vérifiait que la cohérence de gouvernance. Or le moment le plus rentable pour
bloquer une fuite de secret est le diff stagé, avant toute entrée dans
l'historique Git.

## Décision

Adopter un dispositif de diagnostic sécurité **local, reproductible et bloquant**,
appliqué au dépôt parent et aux trois dépôts externes intégrés
(`apps/GeoSylva`, `apps/QGISIA`, `Forge`) :

1. **Orchestrateur unique** `tools/security_diag.py` (cross-plateforme,
   stdlib + uvx) :
   - scan de secrets : diff stagé (`--staged`), commit (`--commit`),
     arborescence suivie par git (mode `quick` et `full`) ;
   - vérifications de configuration ciblées : tags Docker `:latest`,
     wildcard CORS/WebSocket, `shell=True`, `eval`/`exec`, `verify=False`,
     URLs `http://` hors namespaces XML, `usesCleartextTraffic`, etc. ;
   - en mode `full` : Bandit via `uvx`, `pip-audit` sur les exports `uv.lock`,
     `cargo audit` et `npm audit` quand les binaires sont présents ;
   - rapport Markdown horodaté dans `output/security-diag/` (gitignoré) ;
   - **code retour 1 si au moins un finding P0 ou P1** — P2 reste non
     bloquant et documenté.

2. **Hooks Git locaux** sur les quatre dépôts (`tools/install_hooks.sh`) :
   - `pre-commit` : scan des secrets du diff stagé (bloquant) + contrôle de
     gouvernance existant conservé ;
   - `post-commit` : diagnostic rapide en tâche de fond → rapport ;
   - `pre-push` : diagnostic complet bloquant (l'annuler est possible via
     `git push --no-verify` en cas d'urgence assumée).

3. **Anti-faux-positifs intégrés** : reconnaissance des placeholders
   (`changeme`, `nvapi-...`, `$VAR`, `:'var'` psql, `*_password` canoniques),
   allowlist de chemins (tests, fixtures, `web/assets`, `node_modules`,
   scripts de sandbox documentés), marqueurs `nosec`/`noqa`/`usedforsecurity`
   respectés, exclusion des namespaces XML/OGC/W3C pour `http://`.

## Conséquences

- Un secret ne peut plus entrer dans l'historique sans action explicite
  (`--no-verify` ou falsification du hook).
- Les P1/P0 bloquent le push ; les P2 sont tracés dans les rapports et
  arbitrés en audit (ex. `ws_allowed_origins=["*"]` gardé par le validateur
  de production, images `:latest` de la stack viz dev).
- Le premier cycle complet a produit
  `23_QUALITY_MANAGEMENT/AUDITS/SECURITY_DIAG_2026-09-29.md` avec les
  corrections déjà appliquées (`shell=True` → invocation structurée dans
  QGISIA, arXiv HTTP→HTTPS et `defusedxml` dans Forge, 6 paquets vulnérables
  mis à jour, marqueurs `nosec`/`usedforsecurity` justifiés).
- Les dépôts externes gardent leur autonomie : hooks installés dans leur
  propre `.git/hooks`, aucun contenu externe commité dans le parent.

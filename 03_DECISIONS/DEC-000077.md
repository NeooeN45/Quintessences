# DEC-000077 — Contexte RLS des comptes et export des consentements

| Champ | Valeur |
|---|---|
| **ID** | DEC-000077 |
| **Statut** | Validé — correctif implémenté et éprouvé le 2026-08-29 |
| **Date** | 2026-08-29 |
| **Décideur** | Fondateur |
| **Périmètre** | API GSIE — identité, consentements RGPD et export de compte |
| **Précédents** | DEC-000075, DEC-000076, IDENTITE-001, GEO-005 |

## Constat

La recette réelle du compte GeoSylva a révélé que les routes de lecture,
d'acceptation et de révocation des consentements ouvraient une session SQL
générique avant d'appliquer le contexte RLS. La table
`gsie_rgpd_identites.account_consent` force pourtant une politique qui exige
`app.current_user_id`. L'acceptation échouait donc en `500` avec une
`InsufficientPrivilegeError`, alors que la politique PostgreSQL elle-même
était correcte lorsqu'elle était exécutée dans une transaction contextualisée.

## Décision

Réutiliser le fournisseur existant `get_db_user_rls` pour les trois routes de
consentement et pour l'export RGPD. Aucun second mécanisme RLS ni contournement
de la politique de base n'est introduit.

L'export de compte doit également inclure la collection `consents`, avec le
type, la version du document, la date d'acceptation et la date de révocation.
Les secrets d'authentification restent exclus de l'export.

Les tests unitaires réutilisent le même override de session que les autres
routes ; la preuve d'acceptation, de lecture, de révocation et d'export est
complétée par un scénario API réel avec Mailpit.

## Preuves et limites

- `POST /me/consents` répond `201` pour `terms` et `privacy` ;
- `GET /me/consents` restitue l'historique ;
- `DELETE /me/consents/terms` répond `200` et renseigne `revoked_at` ;
- `GET /me/export` restitue les deux consentements ;
- la vérification e-mail, l'annulation de suppression, la reconnexion et
  l'isolation de deux comptes synthétiques sont passées dans la même recette ;
- Google reste `not_configured` et le faux jeton est refusé en `503` tant que
  les identifiants OAuth réels ne sont pas configurés ;
- cette décision ne ferme pas encore la recette Android complète ni le gate de
  suppression finale du worker.

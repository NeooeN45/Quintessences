# DEC-000053 — Ouverture du chantier GSIE Server Meshing

| Champ | Valeur |
|---|---|
| **Statut** | Draft |
| **Date** | 2026-08-03 |
| **Décideur** | Fondateur |
| **Portée** | Transverse — Hub, API GSIE, architecture, roadmap |
| **RFC liée** | RFC-0035 (Draft) |
| **Directive liée** | GSIE-DIR-0012 (Draft) |
| **Précède** | DEC-000010 (UE 5.8 + Cesium), DEC-000013 (Centre de Commandement), DEC-000017 (Phase 4) |

## Contexte

Le Centre de Commandement GSIE actuel (livrable 211, HUB-001) est un
client de visualisation monolithique consommant un seul flux WebSocket
d'une seule instance d'API GSIE. Ce modèle est adapté à un périmètre
régional mais présente trois limites structurelles pour l'évolution
long terme :

1. Pas de continuité spatiale au-delà d'une région.
2. Pas de concentration dynamique de ressources sur les zones actives.
3. Pas de couche de persistance distribuée survivant à la panne d'un
   serveur.

Le Fondateur souhaite évoluer vers un **jumeau numérique environnemental
distribué, continu et persistant** — le **GSIE Server Meshing** —
inspiré des approches de Server Meshing popularisées par les mondes
persistants à grande échelle, adaptées au contexte scientifique,
offline-first et traçable de GSIE.

## Décision

1. **Ouvrir le chantier GSIE Server Meshing** comme direction
   architecturale long terme, cadree par :
   - RFC-0035 (vision et principes)
   - GSIE-DIR-0012 (directive fondatrice)

2. **Acter les décisions structurantes suivantes** :

   | Décision | Valeur |
   |---|---|
   | Périmètre prototype v0 | Mono-région (Landiras, Gironde) |
   | Stratégie d'autorité | Hybride zone spatiale + type d'entité |
   | Dépendance UE6 | Compatibilité anticipée (interfaces abstraites, pas de dépendance hard UE5.8) |
   | Profondeur première itération | Complète (gouvernance + architecture + roadmap + backlog) |

3. **Produire les livrables d'architecture et de roadmap** listés
   dans RFC-0035 §6.2, en statut Draft, pour validation ultérieure
   du Fondateur.

4. **Ne pas interrompre les priorités Phase 4** (14 moteurs, API GSIE,
   Hub UE5.8, GeoSylva, Ignis). Le Server Meshing est une direction
   long terme qui oriente les choix d'implémentation dès maintenant
   (interfaces abstraites, persistance externe, traçabilité) sans
   requérir de livrer un mesh opérationnel immédiatement.

## Conséquences

- 17 nouveaux livrables à produire (Vagues 1 à 4, voir RFC-0035 §6.2).
- Évolution des documents existants : `COMMAND_CENTER_UNREAL.md`,
  `GSIE_MASTER_ARCHITECTURE.md`, `HUB_001_SPECIFICATION.md`,
  `HUB_002_INTERFACE_CONTRACT.md`, `ROADMAP.md`, `PROJECT_MEMORY.md`.
- Aucun impact immédiat sur le code Phase 4 en cours.
- Les nouvelles implémentations (API, Hub, moteurs) doivent adopter
  des interfaces abstraites pour ne pas bloquer la migration future
  vers le mesh.

## Alternatives considérées

- **Attendre avant d'ouvrir le chantier** : rejeté. La vision doit
  être capturée maintenant pour orienter les choix d'implémentation
  Phase 4. Attendre risque de produire du code qui devra être refait
  pour s'adapter au mesh.
- **Remplacer le Hub monolithique actuel par un mesh immédiatement** :
  rejeté. Le Hub monolithique est la cible Phase 4. Le mesh est
  Phase 5+. Une transition brutale compromettrait la livraison
  court terme.
- **Dépendre d'UE6 pour le mesh** : rejeté. UE6 n'est pas publié et
  ses primitives de meshing ne sont pas confirmées. La compatibilité
  est anticipée par abstraction, sans dépendance hard.

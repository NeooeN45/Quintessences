## Contexte

Après ~1 mois de Phase 4, l'état réel mesuré est :

- 14 moteurs implémentés + orchestration
- 28 migrations Alembic, 120 tables sur 6 schémas
- 83 routes API, 1859 tests unitaires (100% couverture, mutation 67/67)
- SDK Python, dashboard admin, outils de visualisation DB
- Sécurité fermée par défaut, observabilité, tests de mutation

Le Fondateur a évalué le projet :

> Le code est plus mature que le produit intégré. Il manque encore la
> preuve complète : terrain → données réelles → preuve scientifique →
> diagnostic → recommandation → validation humaine → application
> cliente/Hub.

**Rapidité** : 9/10. **Qualité technique** : 8/10. **Qualité produit** :
6,5-7/10. Le décalage entre production rapide et consolidation lente
produit des signaux de tension : mémoire dépassée, OpenAPI en retard,
données statiques sur endpoints dashboard, tests concurrents instables.

## Décision

Le Fondateur **décide** une phase de stabilisation courte et ciblée.
Les nouvelles fonctionnalités (nouveaux endpoints, moteurs, migrations)
sont suspendues pendant cette phase.

Trois livrables concrets à produire, dans l'ordre :

### S1 — Restauration DB prouvée

- Backup réel de la base GSIE
- Restore sur une base vierge
- Vérification d'intégrité : row counts, PostGIS, contraintes FK, RLS
- Test automatisé qui reproduit le restore en CI
- Document `GSIE/DOCUMENTATION/DR-RESTAURATION.md`

**Critère de clôture** : test CI vert + document validé.

### S2 — Tranche verticale réelle

- Données réelles : un massif forestier (pas du mock)
- Pipeline complet : ingestion → evidence → knowledge → correlation →
  reasoning → diagnostic → recommendation
- Validation humaine du forestier sur le résultat
- Document `GSIE/DOCUMENTATION/TRANCHE_VERTICALE.md`

**Critère de clôture** : document validé + validation humaine.

### S3 — Validation scientifique + performance

- Au moins un moteur avec prédictions comparées à un ground truth
- Benchmark mesuré : latence API, temps de pipeline, mémoire
- Reproductible : script qui rejoue le benchmark

**Critère de clôture** : script reproductible + rapport de validation.

## Ce qui est suspendu

- Nouveaux endpoints API, moteurs, migrations
- Optimisation de couverture de tests
- Nouvelles intégrations externes

## Ce qui reste autorisé

- Corrections de bugs, maintenance dépendances (CVE)
- Mises à jour de documentation, tests d'intégration/E2E
- Consolidation de la mémoire projet

## Conséquences

Les gates 4 (Science), 5 (Intégration) et 6 (Performance) de la
`ROADMAP.md` passent à ❌ — bloqués par S2 (gate 5) et S3 (gates 4 et 6).

Aucune réarchitecture n'est nécessaire. La qualité technique des
composants existants est jugée suffisante. Le travail porte sur
l'assemblage et la preuve, pas sur la refonte.
